# 設計ドキュメント

## 概要

DiscordBot プロセスは、起動すると `discord.token` で Discord に接続し、
参加しているチャンネルへのメッセージを監視する

メッセージが新規に作成されたときには、次の処理を実施する。

## アーキテクチャ

ユーザー入力

```
User → Discord → DiscordBot → Claude API
```

Claude API からのレスポンス (!discord コマンドの場合)

```
Claude API → DiscordBot → Discord API
           ←
```

Claude API からのレスポンス (!discord send / !discord sendto)

```
Claude API → DiscordBot → Discord API → ユーザー
```

## セッションの管理

チャンネルごとの既存のセッションの扱いは次の通り

- スキルを指定したチャンネル: 毎回新規セッション
- スキルを指定しないチャンネル: 既存セッションの再利用
  - チャンネルに対するセッションがないときは、新規のセッションを作成する
- 新規のセッションの開始時には `<system-context>\n[docs/PROMPT.mdの中身]\n</system-context>\n` をプロンプトの冒頭に付与する

### スキルセッションの再開（メッセージとセッションの対応表）

スキルを指定したチャンネルのセッションは使い捨てだが、Claude 側のセッションは残っているため resume できる。
そこで、スキル実行時に関係したメッセージの ID とセッション ID の対応表を `.message-sessions.json` に保存し、
これらのメッセージへのリアクション／リプライを、そのセッションへの入力として扱う。

- 記録するメッセージ: トリガーになったユーザーの発言、logChannel への実行開始通知、Bot の出力（logChannel・`!discord send/reply/sendto`）、cron 実行の出力
  - スクリプトモードは Claude のセッションがないため記録しない
- 記録する内容: `messageId -> { sessionId, channelId（元のスキルチャンネル）, lastUsedAt }`
- logChannel 上のメッセージに対するリアクション／リプライも受け付け、元チャンネルの設定（workdir など）で実行する
- 再開した回の出力も記録するため、何往復でも続けられる

#### 有効期限

| 経過時間（最終利用から） | 扱い |
|---|---|
| `discord.sessionTtlDays` 以内（既定 7 日） | セッションを再開する |
| TTL 〜 TTL×2 | 期限切れとして logChannel に通知（リプライは新規スキル実行に切り替え、リアクションは通知のみ） |
| TTL×2 超 | 対応表から削除（起動時・保存時・1 時間ごと）。上限 5000 件を超えたら古い順に削除 |

- セッションを再開するたびに、同じセッションの全エントリの期限を延長する
- Claude Code はセッション履歴を `cleanupPeriodDays`（既定 30 日）で自動削除する。期限内でも resume 先が見つからない場合は、期限切れと同様に扱い、そのセッションのエントリを削除する

## メッセージ入力時の流れ

```
1. ユーザーがメッセージ送信
   ↓
2. DiscordBotが受信
   ↓
3. 権限チェック
   - `discord.user` と一致するか
   - `channels` のいずれかの `name` と一致するか
   ↓
4. Claude APIに転送
   - プロンプト文の作成
   ↓
5. レスポンス処理
   - メッセージ取得
   - ファイル添付抽出
   - !discord 検出・実行 (コマンドによっては 4. に戻る)
   ↓
6. ユーザーに返信
```

### プロンプト文の作成

- 発言者が `discord.user` の ID と一致しない場合は処理をスキップ
- 発言されたチャンネルが `channels` のうちのいずれかの `name` と一致するか確認する。一致しなければ処理をスキップする
- 発言に画像が含まれる場合は、`.tmp` フォルダに一時的な名前でファイルをダウンロードする
- プロンプトを実行する。
    - 発言の先頭に `skill` に記載されているスキル名をつける
    - 現在のディレクトリは `dir` に記載されているディレクトリに設定する。省略時はプロジェクトルート。

プロンプトの例

```
id: 1469254290685165578
content: /skill-name text
channel: 1464624036071080082
attachments: .tmp/xxxx .tmp/yyyy
reactions:
```

## ユーザーコマンド (スラッシュコマンド)

Bot 起動時に Discord にスラッシュコマンドを登録する。

- `/clear`: セッションを初期化する。チャンネルに紐づくセッション ID を削除し、次回の発言で新規セッションが開始される。

## ユーザーリアクション時の流れ

- DiscordBot の発言に対するリアクション、かつ、`discord.user` からのリアクションの場合のみ、処理を行う
- プロンプト文を作成して、Claude API 経由で既存のセッションに通知する
  - 対応表にあるメッセージの場合は、そのスキルセッション
  - それ以外は、チャンネルのセッション

```
id: 1469254290685165578
channel: 1464624036071080082
reactions: 2️⃣
```

## ユーザーリプライ時の流れ

- リプライ先が対応表にあるメッセージの場合、スキル名を付けずに、そのスキルセッションを再開してプロンプトを送る
  - プロンプトには `reply_to: <リプライ先のメッセージID>` を付与する
- セッションが期限切れ・見つからない場合は、`reply_to` と `reply_to_content`（リプライ先の本文）を付与して新規スキル実行する
- 対応表にない場合は、通常のメッセージとして処理する
